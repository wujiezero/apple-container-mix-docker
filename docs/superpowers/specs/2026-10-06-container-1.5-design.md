# Apple container 1.5 compatibility fixes

The existing command mappings and Compose state parser remain compatible with
Apple container 1.5.0. This change fixes two previously existing Docker semantics
and updates the documented validation baseline.

`docker start A B` will start each container in order, continue after a failure,
and return a nonzero status if any start fails. Single-container and help calls
will retain direct process replacement for TTY and signal handling. Attaching
to multiple containers will be rejected before starting any container.

An explicit empty entrypoint will bypass the image entrypoint by promoting the
explicit command's first argument to `--entrypoint`. Remaining arguments stay
as separate argv elements, without a shell wrapper. Clearing the entrypoint
without an explicit command will fail rather than inherit image defaults.
Docker run/create, Compose up, and attached/detached Compose run will share this
translation. For Compose run overrides, the last entrypoint option wins.

The shim will remain dependency-free. Regression tests will exercise its CLI
against a recording subprocess, while isolated local containers will verify
real entrypoint and lifecycle behavior on 1.5.0. Existing user containers,
images, networks and volumes will be preserved. Installed symlinks will be
verified after the edit. Commit and push to the current GitHub tracking branch
are authorized by the user's request.
